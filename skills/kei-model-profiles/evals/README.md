# kei-model-profiles evals

Eval cases for the kei-model-profiles skill: how an admin assigns a model
profile to an agent and how a harness resolves it at run time through
kei-proxy and the Agentware socket client.

## Running

Checks are deterministic (case-insensitive string and regex checks in
`evals.json`, no LLM grader). The CI gate (`.github/workflows/agent-evals.yaml`)
runs every case once per model profile on a pull request and 3 times in the
nightly sweep of `main`, and gates on the average pass rate (threshold 0.90).
To tune locally:

```bash
node scripts/run-evals.mjs --skill kei-model-profiles \
  --model-profile glm-5.3-flash --jobs 1 --repeats 3
node scripts/run-evals.mjs --skill kei-model-profiles \
  --model-profile qwen3.8-27b --jobs 1 --repeats 3
```

Run Qwen through the Qwen lock (AGENTS.md, Evals rule 6). `evals-out/` is
ignored by git. Don't commit local benchmark results; the CI gate's report is
the record.

## Cases

1. Assign a profile to an agent: console and `kei model-profiles assign`.
2. No `POST /v1/chat/completions` on the daemon; use `/v1/model-config` or
   `kei-proxy model`.
3. Failover and spend watch are proposed (kei#1164), not implemented.
4. A profile changed mid-session: kei-proxy doesn't cache; the harness
   re-resolves.
5. `no_profile` from `/v1/model-config`.
6. `model profile credential unavailable`: `secret_ref`, `KEI_SECRETS_BACKEND`,
   IAM.
7. The Agentware `model_config` strips the credential by design; no invented
   backend class.
8. A disabled assigned profile fails closed; the workspace default applies
   only without an assignment.

## Widened checks and their negative tests

These checks use a regex or a widened phrase list. Each entry below gives
the final pattern, answers it accepts, and wrong answers it rejects.
`run-evals` grades with the same case-insensitive matching. This section
was generated by running each string against the pattern in `evals.json`.

### Case 3: The response says failover is not implemented today.

Widened from a phrase list after two correct GLM answers said "Kei has no automatic failover". Per orchestrator QC, `fails? closed` and `no longer` were removed: a fail-closed sentence does not say failover is unimplemented, and "no longer exists" implies it once did.

```text
no (automatic |built-in |automated )?(failover|fallback|fail-over)|not (yet )?(implemented|available|shipped)|(doesn.t|does not) exist|(won.t|will not|does not|doesn.t) (automatically )?fail ?over
```

Accepts:

- `` Kei has no automatic failover today `` → match
- `` Failover is not implemented `` → match
- `` Backup profiles are not yet shipped `` → match
- `` Kei does not fail over to another model `` → match

Rejects (wrong answers):

- `` Kei will fall back to the backup profile automatically `` → no match
- `` A disabled profile fails closed `` → no match
- `` Failover no longer exists `` → no match
- `` Yes, Kei fails over when the provider is down `` → no match
