# agentware-sdk evals

Eval cases for the Agentware middleware policy/audit skill. Includes identity
resolution (link.identity()), the third-party harness contract
(AuthProvider/ToolExecutor/SecretProvider), enrollment DENY handling, and
KeiProxyEvaluator construction in Python.

Cases 16-20 cover building an agent end to end: Python model wiring and
tool-call/reasoning parsing (16), the `tool:<name>` policy and `kei policy test`
(17), how the v3 manifest gets loaded (18), the
`agentware.eval-suite.v1` evals (19), and taking the model from a Kei model
profile rather than the socket chat route (20).

Case 18 source truth, Agentware main 6956b68 and kei-cli main 9b71cfb:

- The manifest is v3. `export_kei_tool_manifest` writes only v3 (Python
  `tools/registry.py:49-52`, TypeScript `tools/registry.ts:64`), and the SDK
  sync sends `application/vnd.kei.tool-manifest.v3+json`
  (`kei/tool_sync.py:63`). kei-proxy also accepts a negotiated v4
  (kei-connector-runtime `CHANGELOG.md:44`), but Agentware never produces
  v4, so the check requires v3.
- `kei harness sync --harness custom --manifest` rejects the v3 export.
  kei-cli `internal/app/harness.go:461-463` reads `route` as a string, `:548`
  decodes it, and `:594` re-sends v2. A dry run of kei 0.3.9 on
  `fixtures/kei/tool-manifest.v3.json` exits 2: `cannot unmarshal object
  into Go struct field .0.route of type string`.

## Widened checks and their negative tests

These checks use a regex or a widened phrase list. Each entry below gives
the final pattern, answers it accepts, and wrong answers it rejects.
`run-evals` grades with the same case-insensitive matching. This section
was generated by running each string against the pattern in `evals.json`.

### Case 16: The response says run_inference does not send the tools and to call complete with tools.

Widened after a correct GLM answer wrote `backend.complete(messages, tools=tools)` and "calls `client.complete(messages)` with **no tools**", which the literal `complete(messages, tools)` pattern missed.

```text
complete\(messages,\s*tools|(not|n't|never)[^.\n]{0,40}(send|pass)[^.\n]{0,30}tools|drops? (the )?tools|with \**no tools
```

Accepts:

- `` call backend.complete(messages, tools=tools) yourself `` → match
- `` it calls client.complete(messages) with **no tools** `` → match
- `` run_inference does not send the tools to the model `` → match
- `` run_inference drops the tools `` → match

Rejects (wrong answers):

- `` run_inference sends your tools to the model `` → no match
- `` use run_inference; it passes the tools `` → no match
- `` call run_inference with tool_specs and the model sees them `` → no match

### Case 18: The response says kei harness sync --manifest does not load this manifest.

New check from the case 18 source-truth fix: `kei harness sync --manifest` rejects the Agentware v3 export (kei-cli internal/app/harness.go:461-463, 548).

```text
harness sync[^\n]{0,160}(reject|fail|doesn.t (work|load|accept)|does not (work|load|accept)|can.t|cannot|not (a )?(path|option|supported|work)|string)|(reject|fail|can.t|cannot|doesn.t|does not|won.t)[^.\n]{0,80}harness sync
```

Accepts:

- `` `kei harness sync --manifest` rejects the v3 export because route is a string there `` → match
- `` kei harness sync --manifest fails on this manifest `` → match
- `` you cannot load it with kei harness sync `` → match

Rejects (wrong answers):

- `` Use kei harness sync --harness custom --manifest tools.json to load it. `` → no match
- `` An operator runs kei harness sync --manifest tool-manifest.json `` → no match
- `` kei harness sync --manifest works for the v3 export `` → no match

### Case 20: The response says kei-proxy serve does not serve the chat completions route.

Authored to accept the several ways a correct answer says the daemon has no chat route, while rejecting advice to use it.

```text
chat[_/ .-]?completions?[^\n]{0,120}(not served|isn.t served|is not served|does not serve|doesn.t serve|404|does not exist|doesn.t exist|removed|no such|not (a )?(supported|available))|(not|n.t|no)[^.\n]{0,40}(serve|expose|have|provide)[^.\n]{0,40}chat|\bno\b[^.\n]{0,30}chat[^.\n]{0,30}(route|endpoint)
```

Accepts:

- `` chat_completion targets POST /v1/chat/completions, which kei-proxy serve does not serve `` → match
- `` kei-proxy serve has no chat route `` → match
- `` There is no `POST /v1/chat/completions` endpoint on the daemon `` → match

Rejects (wrong answers):

- `` Do not hard-code the model endpoint `` → no match
- `` Send chat through sock.chat_completion(session, payload) `` → no match
- `` Use POST /v1/chat/completions on the socket `` → no match
